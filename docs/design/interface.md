# Interface and content

The supplied monochrome design is authoritative: white background, #171717 text, #F5F5F5 surfaces, #E5E5E5 borders and black primary actions. Small muted text uses #626262 to preserve contrast. Inter is self-hosted from the pinned font package; source cover artwork retains its original colors.

Navigation is horizontal, with a collapsible top menu on smaller screens. Filters sit above grids and open in a mobile dialog. Detail pages are dedicated routes. Poster space reserves a 2:3 ratio; images load lazily except the featured/detail poster. Grids use 2 columns below 640px, 3 from 640px, 4 from 768px and 6 from 1280px. A full 24-title catalogue page fills those rows; shorter source pages keep their actual count. There is no persistent sidebar.

Media cards have bordered frames, two-line title space, format/year, available episode or chapter counts and up to two source genres. Cover and title links open the detail page; there is no separate details action or bottom action row. A circular 44px save control sits at the upper-right corner, visible on small/touch screens and revealed on desktop hover or keyboard focus. Contrasting focus rings keep it visible over artwork. Save remains independent from navigation. Hover/focus feedback requires no extra metadata request. Failed artwork displays a labelled fallback; missing scores do not produce an empty rating badge. Card skeletons match the poster, corner control and metadata areas without interactive-looking desktop hover controls.

Below 768px, the homepage's popular anime and manga sections use native horizontal scrolling with snap alignment and a next-card preview. Labelled scroll regions support keyboard focus and arrow-key scrolling; card links remain reachable in order. Loading shelves keep the same horizontal shape. There is no autoplay. Catalogue, search and account grids retain their existing columns and pagination.

`shared/ui` owns canonical Button, Modal, loading and error states. Modal focus is captured/restored for programmatic triggers. `shared/feedback` owns offline and polite toast feedback. `MotionConfig` respects the device reduced-motion preference; transforms are limited to brief entry/press/hover feedback. No unpausable movement is introduced.

`content/en/common.json` owns interface copy. `shared/content` supplies typed keys, named interpolation, locale-aware counts and dates. Metadata and user values remain plain data. Errors map centrally from stable codes; raw provider/server exception text is never displayed.

All copy follows the owner's editorial plan. Production editorial review and manual screen-reader validation remain pending even when automated accessibility checks pass.

Account dialogs use one content column: 28px desktop/24px mobile padding, 48px fields and primary/provider controls, 8px label gaps and 16px field-group gaps. Mode buttons share equal columns and keep 44px targets. Mode headings match the active form; recovery is absent from signup. Errors stay with the relevant form, and one centered guest footer closes the dialog. Narrow horizontal shelves align their card edges with page headings instead of offsetting them outside the content baseline.

Loading regions render only their page-shaped skeletons. Their status has an accessible loading name and `aria-busy`; no Loading text node depends on a visually-hidden utility. Discovery dialogs use explicit scoped styles: two equal field columns above 699px, one below, 48px inputs/selects, 8px label gaps and 20px row gaps. Checkboxes, apply actions and preset actions have separate full-width rows. The close icon aligns with the heading; content scrolls within short viewports. Existing filter values, presets and URL behavior are retained.

Personal library, wishlist and collection items use the same MediaCard/grid as discovery. Status or collection position belongs inside the card body; a 44px corner management control opens the existing operations in a dialog. Personal cards have no detached action row. Removal confirmation and versioned changes remain intact. Personal pages share horizontal navigation, left-aligned title/count treatment and 48px form controls with 8px label gaps; there is no alternate personal-page theme.
