# ALCOR engineering instructions

Read the complete [DromoLys protocol](docs/engineering/DROMOLYS_STANDARD_SOFTWARE_BUILDING_PROTOCOL.md) at the start of every development session. D-SSBP v1.0 is mandatory for this project under the owner's instruction of 30 October 2026.

Use both specifications in `docs/product/`. Preserve their scientific, identity, progress, security, content and release contracts. Never replace missing production services with a hidden development bypass.

Inspect, specify, plan, implement, verify/integrate, then validate/accept. Classify risk and record task contracts before consequential implementation. Keep implemented, verified, validated and released distinct. Human review and release decisions must be recorded as pending until they actually occur.

Make one focused commit per verified feature. Include relevant tests and documentation in that commit. Do not rewrite published history, weaken tests, commit secrets, or mix unrelated changes.

Maintain `docs/engineering/error-log.md` for every encountered tooling, build, test and application failure: symptom, cause, correction, verification and unresolved limits. Keep documentation concise and factual.

Parallel agents require explicit authorization, frozen contracts, separate worktrees and nonconflicting ownership under protocol section 15. Logical implementation and verification roles do not by themselves require additional agents.
